# Reel Pops Block Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the last missing widget-kind theme block: a site-wide floating bubble (app embed) that opens the already-shipped lightbox with the merchant's featured reel, dismissible with session-scoped persistence.

**Architecture:** Two small new asset files (`reel-pop.css` for bubble positioning/animation, `reel-pop.js` for dismiss-button + sessionStorage logic only) plus a new app-embed block (`reel-pops.liquid`) that reuses the entire already-shipped lightbox stack (`reel-hls.js`, `reel-lightbox.js`, `reel-trigger.js`) unchanged — no new playback or tagged-products code anywhere in this plan.

**Tech Stack:** Plain Liquid/CSS/JS, no build step — same as the rest of this extension.

## Global Constraints

- This plan touches only `extensions/shoppable-video-widgets/**` — no admin-app (`app/`) file changes, no `shopify.app.toml` change (the REEL_POPS metafield definitions already exist).
- No change to any already-shipped file (`reel-hls.js`, `reel-lightbox.js`, `reel-lightbox.css`, `reel-trigger.js`, `reel-story.js`, `reel-story.css`, or any of the other four blocks) — this plan only adds new files.
- Every reel's poster `<img>` keeps `loading="lazy"` and explicit `width`/`height`.
- No automated test suite covers this extension — run `npm run typecheck`, `npm run lint`, and `npm run test` after every task as the basic sanity gate that nothing else was accidentally touched (same convention as the prior two storefront plans).

### Task 3: Create `reel-pop.js`

**Files:**
- Create: `extensions/shoppable-video-widgets/assets/reel-pop.js`

**Interfaces:**
- Consumes: each bubble wrapper's `data-reel-id` attribute (Task 4 produces it) and a `<button data-reelup-pop-dismiss>` inside it.
- This file does NOT wire the bubble's open-lightbox click — that's handled entirely by the already-shipped `reel-trigger.js`, unchanged. This file only handles dismiss + persistence.

- [ ] **Step 1: Create the file**

```js
(() => {
  document.querySelectorAll("[data-reelup-pop]").forEach((pop) => {
    if (pop.dataset.reelupPopBound) return;
    pop.dataset.reelupPopBound = "true";

    const reelId = pop.dataset.reelId ?? "default";
    const storageKey = `reelup-pop-dismissed-${reelId}`;

    let alreadyDismissed = false;
    try {
      alreadyDismissed = sessionStorage.getItem(storageKey) === "true";
    } catch {
      // sessionStorage unavailable (private browsing, quota, etc.) — treat
      // as not-dismissed; the bubble just won't remember dismissal below.
    }

    if (alreadyDismissed) {
      pop.hidden = true;
      return;
    }

    const dismissButton = pop.querySelector("[data-reelup-pop-dismiss]");
    dismissButton?.addEventListener("click", (event) => {
      // The dismiss button is a positioned sibling of the trigger, not a
      // descendant of it, but stop propagation anyway so a click here can
      // never be misread as a click on the trigger's own open-lightbox
      // button by anything listening higher up the tree.
      event.stopPropagation();
      pop.hidden = true;
      try {
        sessionStorage.setItem(storageKey, "true");
      } catch {
        // Dismissal still applies to this page view; it just won't persist
        // across navigations if storage isn't available.
      }
    });
  });
})();
```
